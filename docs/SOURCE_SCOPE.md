# Original-book source scope

The active source is the 2015 Raja publication already identified by the public production ledger. A lesson must retain its actual book and stable source-question identity. New work cannot silently fall back to another publication or an independent collection.

## Source evidence and review

`production/source-policy.json` pins the existing public extraction fingerprint and exact published starter-review records. New production requires a readable private source matching its reviewed fingerprint, valid question/options/key/explanation records, and stable source IDs. A historical extracted flag or a ready ledger status does not prove current source availability.

Claims record sourceEvidence. An actual comparison of the authored narration and quiz to the source must then create a per-question sourceReview binding the source record, authored content and quiz hashes. Generation and completion recompute those fingerprints. A copied identity, copied evidence object or calculated hash is not approval. No command creates review assertions automatically.

Exact previously published starter content can be repackaged using the already-public ledger and release-report evidence. Changed content, media or audio timing fails replay validation. This exception does not authorize new questions without source evidence.

## Delivery and builds

`npm run source:check` validates the active publication and bundled lessons. Both actual builders invoke the check, including direct Node invocation and the Android builder's selected web directory. Normal pack generation checks lessons plus publication metadata, including truthful produced counts and question identities. A claim can lag in the app display as ready; it cannot become a falsely produced lesson.

The source-scope workflow exercises wrong-source, missing-evidence, changed-content, misleading-metadata and direct-builder regressions. These checks enforce production and delivery; they do not replace clinical review or retrofit restrictions into an already-installed general-purpose importer.

## Recovery and intentional changes

Keep raw source text, annotations, recovery identifiers and archives private. Search the original authorized book file as well as the structured archive when recovery is needed. A fresh or partial extraction needs a documented source comparison, stable mapping and reviewed fingerprint registration; never pretend it has the old bytes. Verify durable backups with a fresh-directory restore.

A genuine future source change needs an explicit user request and deliberate policy/test updates. There is no automatic fallback or policy-bypass flag.
